GitHub Copilot のエージェントモードでは、自律的にコードベースを調査し、変更を提案してファイルを編集し、コマンドを実行します。VS Code の Copilot Chat では、ツールの呼び出しやファイル編集をリアルタイムで確認できます。差分をインラインでレビューし、個々の変更を受け入れるか元に戻し、エディターを離れずに追加のプロンプトを送って作業を調整できます。

この演習では、次の作業を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視する。
- 提案されたファイル編集をレビューして受け入れる。
- 作業中のセッションにライトモードの切り替えを追加するよう依頼する。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントは、ハイコントラストモードを実装中です。作業中、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードへの切り替えも追加します。新しい会話を始めるのではなく、既存のセッションを誘導します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調査するファイル、実行するコマンド、提案する編集が表示されます。各ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み取り、編集、実行を求めるターミナルコマンドなどが表示されます。
3. エージェントがファイルを編集すると、差分がインラインで表示されます。
   - **Keep** を選択すると変更を受け入れます。
   - **Undo** を選択すると変更を元に戻し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開くと、このセッションで変更されたファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などで許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけ承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に変更内容の要約が表示されます。

## ライトモードを追加するようエージェントを誘導する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えも追加します。同じセッションを続けるため、エージェントは前の作業で変更したコンポーネント、スタイル、ローカルストレージの使い方をコンテキストとして保持します。

1. Copilot Chat の入力欄に、次のフォローアッププロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントが既存の変更を調べ、ライトモードの追加を提案する様子を確認します。
3. ハイコントラストモードの場合と同様に、新しい編集をレビューし、各差分で **Keep** または **Undo** を選択します。
4. エージェントが意図しない方向に進んだ場合 (たとえば、切り替えのユーザーインターフェイス (UI) を希望しない形でリファクタリングする場合) は、チャット入力欄の横にある **Stop** を選択して停止し、補足プロンプトを送信します。

> [!TIP]
> 実行中のセッションを誘導すると、最初からやり直すより速く調整できます。フォローアッププロンプトで「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」のように変更を依頼したり、「トグルを増やさず、既存の設定パネルにライトモードを追加する」のように方向を修正したり、「両方のトグルにキーボードショートカットを追加する」のように範囲を広げたりできます。

## 変更されたファイルをレビューする

コミットする前に、エージェントが変更したファイルをすべて確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが含まれているはずです。
3. 変更したファイルをいくつか開き、差分を確認します。Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HTML、ローカルストレージによる設定の保持など、カスタムエージェントのアクセシビリティパターンを確認します。
4. 問題がなければ **Source Control** パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードで実行中のセッションを監視し、各ファイル編集をレビューして受け入れるか元に戻し、コンテキストを保ったまま追加プロンプトで作業を拡張しました。

このレッスンでは、次の作業を行いました。

- エージェントの作業をリアルタイムで監視した。
- 個々のファイル編集を受け入れたり元に戻したりした。
- フォローアッププロンプトで実行中のセッションを誘導した。

次は、アクセシビリティの変更をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが作成した変更をレビューします。
